## Why retire

The forge builds the same ~19,000-target project three times
(library, comparator-internal, open comparator). At
processors=8 the comparator phase OOM-kills the runner (run 9,
proven); at processors=2 every leg misses its time box by
about 1% (run 12). The remaining unknowns are not small: the
nanoda kernel check has never run, so its duration is unmeasured,
and a run with boxes large enough to reach it would occupy the
desktop for roughly a day, for a ceiling of conditional PASS /
unconditional PARTIAL under D5. Twelve runs, including about
31 hours of desktop time in runs 9–12 alone, bought no receipt.
The expected value of run 13 does not clear that cost.

**Reopen conditions:** AxiomMath ships built artifacts or a
release for the pinned tree; or the upstream CFSG M1 is audited
(raising the unconditional ceiling); or a materially faster
runner lane exists. Any reopen starts from the same pin and
this note's run record.

**Close-out actions:** this note and its INDEX row landed; the
forge workflow deleted; the forge guard
(cfsg-corollary-forge-guard) was disabled 2026-11-15 after its
once-only run 12 report. The desktop's `.wslconfig` restore
(processors 2 → 8) is the user's hand on the box and completes
the close-out. The 32-gate verdict lock is untouched; no CFSG
entry is added to it.
