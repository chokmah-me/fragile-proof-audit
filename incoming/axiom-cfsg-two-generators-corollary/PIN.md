## Claim

There is no paper. The claim artifact is the repository README
(GitHub-first claim): every finite simple group is generated by
two elements, proved in Lean on top of AxiomMath/CFSG's proof of
the classification of finite simple groups. This is the
classical two-generation corollary of CFSG. The README states
two theorems, both in `Comparator/Solution.lean`:

- conditional: `CFSGCorollary.exists_closure_pair_eq_top_of_classification`,
  assuming TauCeti's `ClassificationStatement`;
- unconditional: `CFSGCorollary.exists_closure_pair_eq_top`,
  applying the conditional theorem to
  `CFSG.Certified.classification_finite_simple_groups`.

README further states: both theorems depend only on `propext`,
`Classical.choice`, `Quot.sound`; the development is about
18,600 lines of Lean excluding dependencies; the build prints
the axioms each theorem depends on; and of the comparator:
"`comparator.json` lists both theorems, but neither has been
checked with comparator (due to time constraints)". A
configured-but-unrun comparator is the receipt gap this audit
exists to close (harvest recon, 2026-11-05).

## The hypothesis, read at pin (TauCeti @ 6e0c6ac)

TauCeti tarball of the pinned rev — sha256
`682d37f067f62f01b57b296451608f2b45249b7285263cc3cf3e0df144415dcc`
(24,733,825 bytes, 9,730 `.lean` files). Reference copies of the
two load-bearing files are filed in
`tauceti-6e0c6ac-reference/`: `Classification.lean` sha256
`1e36fdabf8ea1b92aa946edaca0911e0d5d6530f9fbb49054a2bdb5de6845c35`;
`Index.lean` sha256
`6e49872e3743dd3b767dde942c2bb1a25e9c22499bb79288078022f392f5630e`.

`TauCeti.ClassificationStatement` is a plain proposition, three
lines, no hidden content:

```lean
def ClassificationStatement : Prop :=
  ∀ (G : Type u) [Group G] [Finite G] [IsSimpleGroup G],
    ∃ i : CFSGIndex, Nonempty (G ≃* i.Group)
```

`classificationStatement_iff` is `Iff.rfl` (the def unfolds to
the quantified form), and `classificationStatement_of_zero`
transfers the universe-0 statement to every universe. The
carriers: `CFSGIndex.Group` sends cyclic p to
`Multiplicative (ZMod p)`, alternating degree to
`alternatingGroup (Fin degree)`, lie indices and sporadic names
to their TauCeti carriers. The Classification file's own header
is candid: no finiteness or simplicity of a listed carrier is
asserted there, and the proposition is not proved in TauCeti.

The list itself (`Index.lean`): `CFSGIndex` is `cyclic (p : ℕ)
(p.Prime)`, `alternating (degree : ℕ) (5 ≤ degree)`, `lie
(ValidLieTypeIndex)`, `sporadic (SporadicName)`; the side
conditions ride in the index as proof fields.
`SporadicName` has exactly the 26 textbook constructors (M11,
M12, M22, M23, M24, J1–J4, HS, McL, He, Ru, Suz, ONan, Co1–Co3,
Fi22, Fi23, Fi24Prime, HN, Ly, Th, B, M), with
`card_sporadicName : Fintype.card SporadicName = 26` proved by
`decide` in the file. `ValidLieTypeIndex` carries the standard-
range and duplicate-representative discipline for the Lie
families.

## M1 first read (2026-11-06, statement level)

- Challenge statements match the README snippets verbatim, and
  the conclusion `∃ a b : G, Subgroup.closure {a, b} = ⊤` is the
  standard weak form of "generated by two elements" (a and b
  need not be distinct; the cyclic case is one generator plus
  the identity). `IsSimpleGroup` carries a Nontrivial
  requirement, so the trivial group is out of scope; it would
  satisfy the conclusion anyway. No vacuity edge found.
- The conditional theorem's hypothesis is
  `TauCeti.ClassificationStatement.{0}`, read above: exactly
  CFSG in TauCeti's form. The Solution proof (six lines) lifts
  it to all universes, takes the index i and the isomorphism,
  transfers finiteness and simplicity along the equiv, and
  applies the library's `twoGenerated_cfsgIndex`. The
  library work (Steinberg's lemmas for Lie type; Jordan's
  theorem for alternating; explicit pairs for sporadics,
  including the Monster via two products in TauCeti's
  Coxeter-type presentation) is where the 18,807 lines live.
- The unconditional theorem is one application: the conditional
  theorem fed `CFSG.Certified.classification_finite_simple_groups`
  through the iff. Its marginal content over the conditional
  theorem is that single step; everything else is inherited
  trust in the CFSG artifact (seam 3).
- Separation is machine-checked by the author:
  `Checks/ImportBoundary.lean` walks the library's transitive
  imports and fails the build if `CFSG.Statement` or
  `CFSG.Certified.Classification` appears, then walks the
  conditional theorem's used constants and fails if any comes
  from outside the library's modules. `Checks` is in
  defaultTargets. Solution.lean is the only file importing the
  classification proof, per its own header and the check.
- Pre-scan at pin (VM, source only, no build): `sorry` appears
  only in `Comparator/Challenge.lean` (exactly 2, lines 27 and
  34, the two challenge theorems, matching the README's "two
  expected sorry warnings"); no `admit`, `native_decide`, or
  `axiom` declarations anywhere in the 91 files.

## Pin seams (forge questions, recorded at pin)

1. **Toolchain is a release candidate.** v4.35.0-rc3. The core
   `lake comparator` merged into Lean at the v4.35.0 release;
   whether rc3 carries it must be probed at forge time. The
   config format here is the standalone comparator's (module
   names `Challenge`/`Solution` under a srcDir lib). Fallbacks
   if the core route is absent at rc3: the standalone
   comparator at the pinned toolchain, or the receipt pair the
   artifact itself supplies (Solution's `#print axioms` plus a
   green `Checks` build).
2. **Building Solution needs the classification module's
   olean.** `Comparator/Solution.lean` imports
   `CFSG.Certified.Classification`, so any comparator run, and
   any `#print axioms` over either theorem, needs that module
   elaborated. Author route: CFSG publishes prebuilt lake-cache
   files for Linux x86_64 only, about 230 GB of disk, fetched by
   a custom script (`lake-cache-get-fast.sh` from
   cfsg-downloads.axiommath.workers.dev) with
   `LAKE_ARTIFACT_CACHE=true`. Runner disk capacity must be
   probed before committing to that route. Source route: Lake
   compiles the parts of CFSG it needs from the pinned
   69cb972 tree (43.1M lines per the 2026-10-27 recon); the
   closure of the classification module is an unknown fraction
   of that. The conditional-first staging still needs TauCeti
   built from source (9,730 files) plus whatever CFSG model
   modules the corollary library itself imports (the library
   does not import the classification proof, per the ImportBoundary
   design, but it does build on CFSG's group models).
3. **The unconditional leg inherits a separate registered
   claim.** AxiomMath/CFSG itself is CLAIM
   `axiom-cfsg-lean-formalization` (harvest 2026-10-27,
   unpicked). This audit can close the conditional leg on its
   own receipts. The unconditional leg will be graded exactly as
   strong as the CFSG artifact unless and until that audit
   runs; the note must say so, not absorb it.
4. **Fresh Mathlib cache.** The rc3-era Mathlib rev b63f6e8
   differs from the release rev used by the Cranston-Li and
   RiemannJensen forges; cache and toolchain installs start
   cold for this artifact.
